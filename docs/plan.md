### 🏛️ 1. 멀티 에이전트 파이프라인 설계 (지능 고도화)

에이전트 간의 데이터 전달은 사람이 읽는 줄글이 아니라, 파이썬이 읽기 쉬운 JSON 형식(Structured Output)으로 주고받도록 강제하여 토큰을 극단적으로 다이어트합니다.

* **🕵️‍♂️ 에이전트 A: 데스크 데스크 (Curation Agent)**
* **역할:** 수집된 10~20개의 '기사 제목 + 첫 문장'만 보고 **가장 중요한 기사 3개**를 선별. (동일한 내용의 복붙 기사 중복 제거 포함)
* **프롬프트 핵심:** "제공된 뉴스 목록 중 중복을 제거하고, 거시 경제 및 투자 관점에서 파급력이 가장 큰 뉴스 3개의 ID만 JSON 배열로 리턴해."
* **효과:** 불필요한 기사 본문을 읽는 토큰 낭비를 원천 차단.


* **🧑‍🏫 에이전트 B: 심층 분석가 (Summarization Agent)**
* **역할:** 에이전트 A가 선택한 3개 기사의 '전체 본문'을 각각 읽고 핵심 내용과 전문 용어를 추출. (해외 기사일 경우 한국어로 자동 번역 요약)
* **프롬프트 핵심:** "이 기사의 팩트를 3줄로 요약하고, 초보자가 모를 만한 전문 용어 2개를 추출해 JSON으로 리턴해." (기사 1개당 1번씩, 총 3번 개별 호출)


* **👨‍💼 에이전트 C: 편집장 (Editor Agent)**
* **역할:** 에이전트 B가 만든 3개의 요약 데이터를 모아, 최종적으로 옵시디언 마크다운(`.md`) 파일 형태의 보고서로 예쁘게 합성(Synthesis).
* **프롬프트 핵심:** "제공된 요약 데이터들을 바탕으로 흐름이 이어지는 데일리 경제 리포트를 작성해. 옵시디언 백링크(`[[ ]]`)를 적극 활용해."

### 🌐 2. 데이터 수집 소스 글로벌 확장 (파이프라인 고도화)

국내 포털에만 의존하면 "해외 발생 ➔ 국내 언론 번역 ➔ 포털 송고"라는 시간 지연과 정보 왜곡이 발생합니다.

* **미국 연방준비제도(Fed) 및 주요 기관:**
* Fed 보도자료(Press Release) RSS 피드 직접 수집. (금리 결정, 파월 의장 발언 등 1차 출처)


* **해외 경제 매체 RSS:**
* CNBC, Yahoo Finance, Investing.com 등의 주요 경제 RSS를 수집.


* **수집 방식 개선:**
* 해외 사이트는 `requests`로 긁으면 Cloudflare 방어에 막히는 경우가 많으므로, 파이썬 `feedparser`를 이용해 가벼운 RSS XML 데이터 위주로 수집합니다. 에이전트 B가 어차피 영어 본문을 한국어로 찰떡같이 번역 요약해 줍니다.

### ⚙️ 3. 제가 추천하는 추가 개선 사항 (엔지니어링 & RAG 대비)

**① 병렬 처리 (비용/시간 단축)**

* 에이전트 B(심층 분석가)가 3개의 기사를 요약할 때, 하나씩 순서대로(for문) 기다리면 시간이 3배로 듭니다. 파이썬의 `asyncio`나 `concurrent.futures`를 사용해 3개의 LLM 요청을 **동시에(병렬로)** 던져서 1초 만에 받아오도록 구성합니다.

**② JSON Schema 강제 (오류율 0%)**

* 에이전트 간 데이터를 주고받을 때 `generate_content`의 설정에 `response_mime_type="application/json"` 옵션을 부여합니다. 이렇게 하면 LLM이 쓸데없는 인사말("네, 요약해 드릴게요!")을 하지 않고 완벽한 데이터 덩어리만 반환하여 파이썬 에러가 날 확률이 0%가 됩니다.

**③ 옵시디언 메타데이터(YAML) 강화 (RAG 최적화)**

* 추후 옵시디언의 데이터를 RAG(검색 증강 생성)에 활용하려면 검색이 쉬워야 합니다.
* 에이전트 C가 글을 쓸 때, 단순히 텍스트만 쓰는 게 아니라 파일 맨 위에 아래와 같은 프론트매터(Frontmatter)를 엄격하게 작성하도록 지시합니다.
```yaml
---
날짜: 2026-08-11
주요키워드: [연준, 금리인하, 삼성전자]
시장분위기: Bearish (하락장)
---

```

### 🗺️ 전체 시스템 워크플로우 요약

1. **[수집]** 네이버 API(국내) + Fed/CNBC RSS(해외)에서 기사 제목/링크 20개 긁어옴.
2. **[에이전트 A]** 20개 제목을 보고 TOP 3 선정 ➔ 원문 텍스트 3개 추출(`trafilatura`).
3. **[에이전트 B]** TOP 3 원문을 각각 JSON 데이터로 요약/번역 (병렬 처리).
4. **[에이전트 C]** 요약된 JSON들을 모아 하나의 완벽한 Markdown 리포트 작성.
5. **[저장]** 라즈베리파이 폴더에 저장 (추후 동기화 대기).


### 완벽한 백그라운드 자동화: Crontab 등록 상세 가이드

Step 1. 실행 스크립트(run_agent.sh) 준비
프로젝트 폴더(/home/pi/economySummary) 안에 run_agent.sh 파일이 잘 있는지, 내용이 맞는지 확인합니다.

Step 2. Crontab 편집기 열기

Bash
crontab -e
(처음 실행하면 어떤 에디터를 쓸 거냐고 묻는데, 가장 쉬운 1 (nano)을 누르고 엔터를 칩니다.)

```Plaintext

0 18 * * * /home/pi/economySummary/run_agent.sh >> /home/pi/economySummary/cron.log 2>&1
```

Step 4. 저장하고 나오기

Ctrl + O 누르고 Enter (저장)

Ctrl + X 누르기 (종료)

1. 🌐 번역 및 노이즈 제거 전담 에이전트 (Pre-processor)
활용 자원: Lite 모델 + 대량의 TPM

문제점: 현재 Heavy 모델(분석가)이 영어 기사를 읽고 번역과 심층 분석을 동시에 수행하고 있습니다. LLM은 두 가지 복잡한 태스크를 동시에 주면 추론 능력이 떨어집니다.

해결책: 분석가에게 넘기기 전, Lite 모델이 먼저 8개 기사 전문을 완벽한 한국어로 번역하고, 광고나 불필요한 서론(노이즈)을 모두 잘라내는 '전처리'를 수행합니다.

효과: Heavy 모델은 오직 '순수 경제 논리 분석'에만 100%의 지능을 집중할 수 있어 분석의 깊이가 압도적으로 달라집니다.

2. 🌡️ 시장 심리 지수 (Market Sentiment) 에이전트
활용 자원: Lite 모델 + 대량의 TPM

구현: 데스크가 8개를 고르고 버려지는 나머지 42개의 기사들이 너무 아깝습니다. Lite 모델에게 수집된 50개 기사의 제목과 요약을 통째로(대량 토큰) 던져주고, "오늘 시장의 공포/탐욕 지수(0~100)와 투심을 평가해"라고 지시합니다.

효과: 리포트 최상단에 "오늘의 투심 온도: 🥶 32도 (공포 국면)" 같은 정량적 지표가 추가되어, 뉴스 요약을 넘어선 '시황 대시보드' 역할을 하게 됩니다.

3. 🧠 장기 기억 합성 에이전트 (Memory Synthesizer)
활용 자원: Lite 모델 + 대량의 TPM

구현: 현재는 최근 3일 치의 짧은 요약(Overview)만 기억으로 넘겨주고 있습니다. 이를 확장하여, 매 주말(토요일)마다 Lite 모델이 이번 주 5일 동안 저장된 전체 리포트 텍스트(엄청난 토큰)를 모두 읽고 '주간 거시경제 트렌드 변화 리포트'를 합성하여 DB에 별도로 저장합니다.

효과: 다음 주 평일에 분석을 진행할 때, "지난주부터 이어지는 흐름"이라는 훨씬 더 장기적이고 거시적인 뷰(View)를 가질 수 있습니다.

4. 🎙️ 팟캐스트/유튜브 스크립트 변환 (Multi-Format)
활용 자원: Lite 모델

구현: 편집장(Agent C)과 검수자(Agent D)가 완벽한 마크다운 리포트를 만들어내면, 마지막에 Lite 모델을 한 번 더 호출하여 이 마크다운을 "안녕하세요, 오늘의 경제 브리핑입니다..."로 시작하는 3분짜리 오디오용 대본(Script)으로 변환합니다.

효과: 텍스트로 읽는 것을 넘어, 추후 TTS(Text-to-Speech) API만 하나 붙이면 라즈베리파이가 아침마다 리포트를 라디오처럼 읽어주게 만들 수 있습니다.

모두 추가 비용(API 한도 소진) 없이 남아도는 Lite 모델의 자원만으로 충분히 구현 가능한 훌륭한 기능들입니다.

## 외부 접속 방식
Cloudflare Tunnel (가장 권장하는 모던 방식): 공유기 포트포워딩 없이 라즈베리파이를 외부에 안전하게 노출하는 터널링 기법입니다. 해커들의 악의적인 포트 스캐닝으로부터 홈 네트워크를 완벽히 숨길 수 있으며, 무료로 HTTPS 도메인까지 발급해 줍니다. 라즈베리파이에 FastAPI나 단순 파이썬 웹 서버(python -m http.server)를 띄운 뒤 Cloudflare 데몬만 실행하면 즉시 외부 접속이 가능해집니다.

GitHub Pages / Vercel 연동 (정적 웹 호스팅): 회원님께서 이미 마크다운 리포트를 깃허브에 백업하고 계신 환경을 100% 활용하는 방법입니다. MkDocs나 Hugo 같은 정적 사이트 생성기를 연동해두면, 깃허브에 새로운 리포트가 Push 될 때마다 자동으로 깔끔한 블로그 형태의 웹사이트가 업데이트됩니다. 라즈베리파이의 서버 자원을 전혀 쓰지 않는다는 것이 가장 큰 장점입니다.

Notion API 연동 (노코드 방식): 서버를 직접 띄우는 대신, 파이썬 파이프라인의 마지막 단계에서 완성된 마크다운 텍스트를 Notion API를 통해 회원님의 노션 워크스페이스로 쏘아 보내는 방법입니다. 외부에서 스마트폰 노션 앱만 켜면 완벽하게 조판된 리포트를 즉시 볼 수 있어 모바일 접근성이 압도적으로 좋습니다.(학생일 때 교육자 업글 가능)
